Software Quality

What is "software"?

IEEE definition (Frame 2.1): Software is computer programs, procedures, and possibly associated documentation and data pertaining to the operation of a computer system.
ComponentMeaning
Computer programsCode.
ProceduresThe order and schedule in which programs are performed, the method employed, and the person responsible for the activities.
DocumentationRequirements reports, design reports, program descriptions, user's manual, programmer's software manual.
DataParameters, codes and name lists, standard test data.

Errors, faults & failures

These three terms describe successive stages of the same underlying problem:

Software error

Made by a programmer — a grammatical error in code, or a logical error in carrying out one or more of the client's requirements.

Software fault

A software error that can cause improper functioning of the software in general or in a specific application.

Software failure

Disruption of the use of the software caused by triggering ("activating") a certain fault.

A fault becomes a failure only when it is activated. Many faults are never activated because users never exercise the affected feature, or because the specific combination of conditions needed to trigger the fault never occurs.

9 reasons for software errors

Software errors trace back to nine recurring root causes across the lifecycle:

1. Faulty requirements definition

Erroneous, absent, incomplete, or unnecessary requirements.

2. Client–developer communication failures

The classic "tree swing" problem — what the customer explained, what the account manager understood, what the project manager defined, and what was actually built rarely match.

3. Deliberate deviations from software requirements

Reusing modules without adapting them to new requirements, omitting functions under budget/timeline pressure, or developer-initiated unapproved "improvements." Even "minor" changes can eventually cause errors.

4. Logical design errors

Erroneous algorithms, erroneous boundary conditions, or omission of required system states.

Example A real-time computerized boiler must react to combinations of temperature and pressure — but no reaction is defined for when temperature exceeds 120°C and pressure is between 6 and 8 atmospheres.

The lecture also illustrates common logical/memory bugs in C, such as leaking or mismanaging heap memory:

void main()
{
    int *p, *q;

    p = (int *)malloc(sizeof(int));
    q = (int *)malloc(sizeof(int));
    *p = 10;
    *q = 20;
    *p = *q;
    printf("%d\n", *p);
}

A corrected pattern checks the allocation and frees the memory it owns:

int main()
{
    int *p;
    p = (int *)malloc(sizeof(int));
    if (p == 0)
    {
        printf("ERROR: Out of memory\n");
        return 1;
    }
    *p = 5;
    printf("%d\n", *p);
    free(p);
    return 0;
}

5. Coding errors

Misunderstanding the design documentation, linguistic errors in the programming language, and errors in data selection.

6. Non-compliance with documentation & coding instructions

Teams are required to comply with templates and coding instructions; non-compliance causes errors.

This becomes critical with multiple teams working in phases — a non-complying team's errors snowball, increasing the probability of system failures.

7. Shortcomings of the testing process

Incomplete test plans that leave portions of the software untested, failure to document/report detected errors, failure to promptly correct detected faults, and incomplete corrections due to negligence or time pressure.

8. Procedure errors

Incorrect procedures adopted for a calculation. Worked example from the slides:

9. Documentation errors

Omission of software functions, errors in explanations/instructions given to users, and listing of non-existing functions — features planned early but later dropped, or features active in a previous version but cancelled in the current one.

Software quality — Pressman's definition

"Conformance to explicitly stated functional and performance requirements, explicitly documented development standards, and implicit characteristics that are expected of all professionally developed software."

This implies three requirements the developer must satisfy for quality assurance:

  • Specific functional requirements — mainly the outputs of the software system.
  • The software quality standards stated in the contract.
  • Good software engineering practices reflecting state-of-the-art professional practice — required even when not explicitly mentioned in the contract.

Software quality assurance

IEEE definition (Frame 2.5):
  1. A planned and systematic pattern of all actions necessary to provide adequate confidence that an item or product conforms to established technical requirements.
  2. A set of activities designed to evaluate the process by which the products are developed or manufactured. Contrast with quality control.
Expanded definition (Frame 2.6): Software quality assurance is a systematic, planned set of actions necessary to provide adequate confidence that the software development or maintenance process conforms to established functional technical requirements as well as the managerial requirements of keeping schedule and operating within budgetary confines.

Quality control vs. quality assurance

Quality control

"A set of activities designed to evaluate the quality of a developed or manufactured product" (IEEE, 1991) — done once production is complete.

Quality assurance

A variety of activities performed throughout the development and manufacturing processes, substantially reducing the rate of products that do not qualify for shipment.

SQA and software engineering

Software engineering is defined as: (1) the application of a systematic, disciplined, quantifiable approach to the development, operation and maintenance of software — i.e. the application of engineering to software; and (2) the study of approaches as in (1).

When making decisions about software methodologies and tools, SQA considerations must be added to the efficiency and economy considerations normally associated with software engineering.
